# ddz-hall —— 斗地主：大厅 + 房间列表 + 房卡

用 `14-architecture.md` 那套分层写的完整示例。**能跑、有单测、有网页端**。

```bash
tsf build .
./run-web.sh             # 起游戏服(9061) + 页面(8080)
# 浏览器开三个窗口，分别用 tok-a / tok-b / tok-c 登录
php85 client.php         # 或者命令行三开验证全链路
php85 tests/run.php      # 规则单测：72 条断言，不编译、不起服务
```

- **网页端**：`http://127.0.0.1:8080/`，三个窗口各用不同 token，能完整打完一局
- **命令行**：`client.php` 模拟三个玩家跑完"登录→建房→列表→加入→准备→开始→叫分→出牌"

## 功能

| 功能 | 说明 |
|:--|:--|
| 房卡 | 档位 1/2/5 张，新玩家 10 张，建房即扣 |
| 房间列表 | 房号、档位、人数、等待/对局中 |
| 准备 + 开始 | 三人齐 → 各自准备 → 房主开始 |
| 叫地主 | 0-3 分轮流叫，叫 3 立即结束，三家不叫重新发牌 |
| 出牌 | 14 种牌型，炸弹/王炸翻倍 |
| 结算 | 叫分 × 倍数 × 档位，地主双倍 |
| 续局 | 结算后房主点"再来一局" |
| 断线重连 | 座位保留 30 秒，同 uid 再进同房间自动恢复 |
| 单测 | Domain 层 72 条断言，不需要编译 |

## 网页端

`web/index.html` 是单文件，原生 JS，**自己实现 TSF 帧编解码**（8 字节头，不到 20 行）——
引一个协议库反而更重。

页面由独立静态服务器托管（`run-web.sh` 里的 `python3 -m http.server`），
游戏服只监听 WebSocket。所以前端里 `WS_PORT` 写死 9061，不能用 `location.host`。

### 前端怎么验证（没有浏览器时）

两个工具，都在 `tools/`：

```bash
node tools/ws-smoke.js      # 用 node 扮演浏览器：连接 → 登录 → 拉列表
php85 tools/frame-check.php # 拿 JS 编出来的一帧给 PHP 解，确认格式一致
```

`ws-smoke.js` 里的 `buildFrame` / `drainFrames` 是从 `index.html` **原样抄**过来的，
所以它能通就说明前端协议层是对的，剩下的只是 DOM 交互。

实测输出：

```
连接 ws://127.0.0.1:9061/
已连接，发登录帧
PASS 登录成功 uid=1001
PASS 收到房间列表，共 0 个
OK 前端收发逻辑可用（帧编解码 / 登录 / 列表）
```

## 几个设计决定，以及为什么

**牌用 int 不用对象**。一副牌 54 张，每局频繁比较、排序、做频次统计。`int` 的数组操作
是 AOT 下最快的形式；`Card` 对象会带来 54 次分配和每个属性访问一次间接。牌是**值**，
没有身份、没有生命周期。

**房间状态全放成员变量，不放静态属性**。静态属性在进程里是全局的，两个房间同时开
手牌会互相覆盖；成员变量随 Service 销毁一起没了。

**大厅不暴露 `roomList()` 给房间调**。第一版写了 `public function roomList()`，让房间直接调，
等于把两个 Service 焊死在一个进程里——拆进程那天会发现调不通。现在列表请求也是
发消息进来的，房间和大厅之间只有地址 + 消息。

**所有网络消息先进大厅**。main.php 的 handler 只投递，不知道"谁在哪个房间"；
那份 uid→房间的映射只有大厅维护，不存第二份。

**断线不取消定时器**。断线时挂一个 30 秒的 kick 定时器，重连时不取消它，
而是在 kick 回调里检查"这个人还在离线吗"。少一份要维护的定时器 id。

**网页端自己实现 TSF 帧编解码**。8 字节头（4 字节总长 + 2 字节 msgId + flags + 保留）
不到 20 行 JS，比引一个协议库轻。

## 简化（不影响玩法正确性）

| 简化 | 真实做法 |
|:--|:--|
| 房卡在内存，重启即清 | PlayerService + DB + 流水 |
| 房间打完整局后，人走完才销毁 | 可配置空房间回收时间 |
| 断线重连靠"同 uid 再 JOIN 同房间" | 客户端自动重连 + 大厅记住 uid→房间 |
| 前端"提示"只匹配单张/对子/三张 | 完整牌型搜索（等于把 Pattern 搬到 JS） |

## 牌型覆盖

单张、对子、三张、三带一、三带二、顺子、连对、飞机、飞机带单、飞机带对、
四带二、四带两对、炸弹、王炸。

比大小：王炸 > 炸弹 > 同型同长比主点数。不同型不同长一律压不了
（炸弹压普通牌是唯一的跨型例外）。

**飞机带翅膀的严格性**：`333444 + 55` 不是合法"飞机带单"——翅膀必须真的是单张。
只数"剩余张数够不够"会把对子拆成两个单张，属于误判（会让牌型比对全乱）。
相关断言在 `PatternTest` 里。
