# mmo-mini —— 一个房间的实时世界（900 行）

**定位**：**帧循环 + AOI + 增量同步**的最小完整实现。想看"万人同屏"的技术骨架，
但不想读几万行，看这个。

```bash
./run-web.sh     # WebSocket 9401 + 网页 8081
# 浏览器打开 http://127.0.0.1:8081/ ，用方向键走动，多个标签页能看到彼此
```

## 覆盖了什么

| 能力 | 实现位置 |
|:--|:--|
| 固定帧循环（20Hz，`frameMs` 默认 50） | `pkg/frameloop` 的 `FrameLoop`，在 `MmoService` 构造 |
| AOI 视野（按半径查询） | `pkg/aoi` 的 `Grid` |
| 增量同步（只推变化） | 每帧比对快照，只发新增/移动/离开 |
| 客户端预测 | `web/index.html` 里本地先动，再以服务端为准 |

## 只有两个源文件

`MmoService.php`（398 行）和 `Msg.php`（24 行）。所有逻辑在一个 Service 里——
**这是刻意的**：AOI 和帧循环的正确性靠"每帧都看到全量状态"，
拆成多个 Service 反而要把状态搬来搬去。

到几千人同屏时该拆（一个房间一个 Service，或者按格子分片），但那是另一个量级的事，
`docs/guide/03-gameplay.md` 讲了边界在哪。

## 看什么

- `MmoService` 里 `MSG_TICK` 的处理 —— 一帧里做了什么，顺序很重要
- `web/index.html` —— 客户端怎么处理"我的位置和服务端不一致"

## 注意

它是**一个房间**的世界，不做分片。要跨房间/跨服看 `sharded-world`。
