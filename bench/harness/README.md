# 测量 harness

> 存在的理由：编解码那次测量我先报出"+55%"，复核后只有 "+14%"。
> 原因是每个变体只跑一次、顺序跑，把机器漂移记成了优化收益。
> 这个工具把正确做法固化成默认行为。

---

## 用法

```bash
cd /data/TypeServer/bench/harness

php85 bench.php list                      # 看有哪些场景
php85 bench.php run codec --reps=5 --secs=4 --json=../results/codec.json
php85 bench.php run packet_size --reps=3
```

参数：

| 参数 | 默认 | 说明 |
|:--|:--:|:--|
| `--reps` | 5 | 每个变体采样轮数 |
| `--secs` | 5 | 每轮压测时长 |
| `--conns` | 场景内定义 | 压测连接数 |
| `--json` | 无 | 原始采样落盘路径（自动建目录） |

---

## 它替你做了四件事

1. **交替采样**：每轮把所有变体各跑一次（A→B→A→B），机器漂移被均摊，而不是全记在后跑的那个变体上。
2. **配对比较**：每轮算一次 `B/A` 比值，再取比值的中位数。同一轮内两个变体是紧邻执行的，**共同漂移在做比值时被约掉**——这比看绝对中位数可靠得多。
3. **MAD 剔除离群值**：用中位数绝对偏差而不是标准差，偶尔被调度打断的点不会污染结果。
4. **诚实拒答**：离散度超过阈值就明确说"绝对值不可用"，而不是硬给一个数字。

---

## 输出怎么读

```
   指标              php              native           差异(最后-首个)
   吞吐 msg/s    34,738          37,749             +8.7%
   ...
   配对比较（每轮 native / php）：
     第1轮: 32,398 → 39,050  = 1.205x
     ...
     中位比值: 1.144x  →  native 相对 php +14.4%   （未剔离群值: 1.144x = +14.4%）
     剔除 0/5 轮   离散度(剔除后): 7.4%

   稳定性: 最大绝对离散度 11.8%（阈值 15%）
   ✔ 离散度合格，结果可用。
```

**优先看"中位比值"那一行**，不要看上面的绝对中位数差异。理由：绝对值会被"某一轮机器整体变慢"带偏（两个变体一起掉），而比值不会。

同时看两个信号：

- **剔除轮数**：0/5 最好。若 ≥30%，剔除后的离散度会偏乐观，要以"未剔离群值"那行为准。
- **绝对离散度**：>15% 说明环境不稳，此时只有配对比值勉强可用，最好复测。

## 加新场景

编辑 `scenarios.php`，加一项：

```php
"my_scenario" => [
    "desc" => "说明",
    "server" => [
        "bin" => "/abs/path/server",     // 被测二进制
        "cwd" => "/abs/path",            // 工作目录（配置从这里读）
        "port" => 9001,
        "proc" => "server_name",         // pkill 用的进程名
        "config" => "/abs/path/config/tsf.json",  // 变体切换改这个文件
    ],
    "variants" => [
        "A" => ["set" => ["protocol.frame" => "php"]],
        "B" => ["set" => ["protocol.frame" => "native"]],
        // 也可以覆盖压测端：["set" => [...], "loader" => "/abs/path/load_xxx"]
    ],
    "loader" => [
        "bin" => "/abs/path/load_tsf",
        "conns" => 32,
    ],
],
```

约束：**压测端必须输出一行 `SUMMARY ... rate=... p50=...ms p99=...ms`**（现有 `load_tsf` 就是这个格式）。

## 已知边界

| 边界 | 说明 |
|:--|:--|
| WSL2 环境噪音大 | 绝对吞吐波动可达 ±30%，务必用配对比值；需要精确绝对值时应上真机 |
| 变体数 > 2 | 配对比较只对两个变体输出；三个以上只能看绝对中位数（噪声敏感） |
| 服务端启动开销 | 每轮重启服务；若被测项与启动有关，应改成"启动一次、连打多轮" |
| 只测吞吐与延迟 | CPU/消息靠 `/proc/PID/stat` 采样，采的是服务端主进程，Swoole 多进程时可能偏低 |

---

## 踩过的坑（都修在代码里了）

1. **端口没释放就启新进程** → 压测打到正在退出的旧进程，那一轮吞吐腰斩。现在先等端口空出来，并校验新进程存活。
2. **压测端用 EPOLLET 却提前 break** → 内核里还有数据但再也不会收到事件，连接随机卡死。现在必须读到 `EAGAIN`。
3. **剔除完离群值再算离散度** → 剩下 3 个点当然很"稳"。现在会显式打印剔除比例，超 30% 就警告。
